# method/

The operating model. One markdown file per section, written as each planning
session concludes — so this folder is the running record of decisions, not a
write-up produced at the end.

| File | Section |
|------|---------|
| `00-overview.md` | How to read this, and the shape of the process |
| `01-frame.md` | The decision the system exists to improve, and who makes it today |
| `02-value.md` | Value metrics, baselines, and what is measured versus assumed |
| `03-requirements.md` | The three requirement classes and how each is verified |
| `04-dataset.md` | Dataset design and why the world is kept separate from the labels |
| `05-golden-set.md` | Case inventory, labelling protocol, holdout discipline |
| `06-harness.md` | Gates, runner, scorecard, and how a build is admitted |
| `07-release-monitor.md` | Shadow → advisory → operating rhythm, and what is monitored |
| `annex-v1-postmortem.md` | What v1 got wrong, and which requirement each defect produced |

Markdown deliberately: version-controlled, diffable, and readable on GitHub
without downloading anything. Any Word or PDF pack is an export at the end,
never the working format.
